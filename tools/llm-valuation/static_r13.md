## 2. 推定の方法

「推定価値」には3種類ある。上場株の時価総額、非上場企業の取引・評価の指標、事業を切り出した仮定の値。事業の切り出しには純負債を引く前の値もあるので、厳密にそろった株式価値の合計ではない。行ごとに、何の価値を測っていて、いつの価格・収益を使ったかを確かめてほしい。

| 値の種類 | 推定のしかた |
|---|---|
| 上場企業の全社値 | 行に書いた日時の時価総額。10/23終値と10/26場中値などが混ざっていて、同じ時刻の値ではない |
| 事業の切り出し | 「事業売上の年換算×AI比率×LLM比率×倍率」か「全社時価総額×価値の配賦率」。開示と仮定を分けて書く。Alphabetの別建て300Bのような追加分も式に書く |
| 非上場の成立価格 | 直近の成立ラウンドのpost-moneyを優先する。pre-moneyでの代用、株の種類の違い、二次取引・モデル指標は、例外として書く |
| 観測値から調整した推定 | 成長の指標などから、既存の価格へつなぐ根拠がある場合に限る。交渉中の価格・未完了のテンダー・IPOの期待を、成立価格の代わりにしない |
| 価格を確認できない行 | 過去の価格、日付不明の一覧値、調達額からの逆算などの暫定値だと明記する。資金調達額・融資・契約総額を、株式価値としてそのまま足さない |
| 買収合意済み・未完了 | 株主への対価を基準にする。World Labs 8.2、Hugging Face 11.9は未完了なので独立の行に残す。買い手の行に同じ対価を足さない |

注意すること：

- レンジは調査者のシナリオの幅で、統計的な信頼区間ではない。今のレンジの例は、Meta 30〜400B、Apple 0〜100B、Alphabet 約522〜1,173B。収益の開示がほとんどない行では、0を含む幅にも意味がある。
- 本表には全社値の例外がある。Databricks、Canva、Figma、Notion、Superhuman、Celonis、Gongなどは、従来の事業も含めた全社値で載せた。一方で、SnowflakeやMongoDBなどはLLM関連の部分を切り出した。ラウンド10からは、既存事業にAI機能を足しただけの会社を参考表に回している。ただ、それより前のラウンドで入れた全社値の例外は、まとめて移してはいない。本表を「AIが本業の会社だけ」「純粋なLLM部分だけ」とは読まないでほしい。
- 機能の分類（1〜9）とは別に、①②③のどの合計に入れるかを決めている。言語・視覚・行動のモデルや、生成的な世界モデルを中核にしたロボット・自動運転、AI設備などは、③の境界例として入れる。一般的な自動化や、AIとの提携があるだけでは入れない。WayveやMomentaは本表の境界例、Andurilは参考表、Helsingは不採用の記録（§5）にある。
- 細分類の先頭のラベル（［全社値・AI本業］［全社値・例外］［切り出し］［境界・③のみ］）は、その行の値が何を測っているかを示す（ラウンド13）。［全社値・例外］は、本業がAI以前からある事業の全社値で、参考表（§4.10）の会社と同じ性質のもの。厳格版の合計からは外している。
- ※は、価格の時点・根拠・取引条件・算定に大事な留保がある行の印。2026年の新しい価格が未確認の行に加えて、元のノートが付けた留保（自己申告の値、換算の仮定など）も残している。具体的な理由は各行を読んでほしい。※が無い行が、成立価格で裏付けられた高精度の値だという意味ではない。
- 株式価値を比べるための合計で、市場の売上や投資額ではない。顧客と供給者の企業価値を並べることと、同じ会社・子会社・持分を重ねて数えることは別の問題として扱った。
- **全社価値で載せた行の「LLM部分だけ」の試算。** ラウンド2-Cは、全社価値で載せた行もLLM部分を切り出してそろえる案を出した。ただし配賦の比率は調査者のシナリオで、会社の開示ではない。そこで主の値は全社価値のままにして、試算は参考として下に並べる。
